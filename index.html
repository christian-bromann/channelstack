Test harness for Slack, GitHub, Linear and Notion apps

Your app’s whole world, on localhost.

channelstack recreates Slack, GitHub, Linear and Notion on your machine, for the bots, integrations and AI agents you build on them. Script the people, let your app answer through its real code path, and assert on what a person would see. Signed webhooks, real payload shapes and real ids, with no changes to how your app works.

Four platforms, one API

Everywhere your app gets an event.

One package fakes all four, with the people, events and API calls apps actually use. Use one in a test, or several when your app spans them. Discord, Stripe and email come next.

{ slack }

DMs, mentions, threads, buttons and the agent view, with progress streams rendered the way people see them.

Why channelstack

Mocks test your mock. channelstack tests your app.

Integrations break in the gaps between systems: a webhook signed the wrong way, a payload shape that changed last month, a stray progress message nobody asserted on. channelstack closes those gaps.

Your app’s real code path

channelstack env points your app’s own SDKs at slack.localhost, github.localhost and friends. Apps with hard-coded hosts use proxy mode instead: set HTTPS_PROXY and trust a CA that only that app sees.

Shapes that can’t drift

Every response and webhook is checked against the providers’ own schemas: OpenAPI descriptions, GraphQL introspection and recorded traffic. When a platform changes, your build goes red instead of quietly wrong.

People, not payloads

Write ana.click("Approve", { message }) instead of hand-building a block_actions body. People post, reply, review, delegate and press Stop, with correct signatures, retries and delivery IDs.

Assert what people see

Streams, status lines, edits and ephemeral messages render into one transcript. toHaveRepliesFrom(…, { count: 1 }) catches the double post. not.toContainText catches the leftover “Thinking…” reply.

In proxy mode, requests to hosts channelstack doesn’t emulate pass through untouched.

Examples

Same API on every platform.

Learn it once with Slack and the rest read the same: people act, resources are read, matchers wait for what a person would see.

test("answers on the issue and ignores itself", async ({ github }) => {  const mo = await github.createUser({ login: "mo" })  const repo = await github.createRepo({ collaborators: [mo], apps: [github.app] })  const issue = await mo.openIssue({ title: "Login 500s on Safari" }, { repo })  const comment = await mo.comment("@my-agent can you take a look?", { issue })  await expect(issue).toHaveCommentFrom("my-agent", { text: /Safari/ })  // the same delivery again must not start a second run  await comment.delivery!.redeliver()  await expect(issue).toHaveCommentsFrom("my-agent", { count: 1 })})

What channelstack handles

  • Installs the App only on repos you list in apps
  • Signs each delivery with X-Hub-Signature-256
  • Redelivers with the same GUID, the way GitHub does
test("Stop ends a working session", async ({ linear }) => {  const kai = await linear.createUser({ name: "Kai" })  const team = await linear.createTeam({ key: "ENG", members: [kai] })  const issue = await kai.createIssue({ title: "Migrate billing cron" }, { team })  const session = await kai.delegate(linear.app, { issue })  await expect(session).toHaveActivity({ type: "thought" })  await kai.stop({ session })  await expect(session).toHaveSessionState("complete")})

What channelstack handles

  • AgentSessionEvent in Linear’s current shape
  • The prompted event carrying the stop signal
  • Every GraphQL response checked against Linear’s schema

Compared

Between mocks and a real workspace.

Real sandbox workspaces are slow, shared and flaky in CI. Mocks are fast but only prove your code matches your own guess. channelstack keeps the speed and drops the guessing.

Quick start

First passing test in three steps.

STEP 1

Install

One package: the server, the CLI, the UI and the test integrations.

npm i -D channelstack
STEP 2

Point your app at it

Each fake comes with an app named my-agent. Tell channelstack where your app takes events, then start the app the way you always do, with channelstack’s environment.

$ CHANNELSTACK_SLACK_WEBHOOK_URL=https://my-agent.localhost/slack/events npx channelstack & $ npx channelstack env >> .env.local $ portless run my-agent pnpm dev
STEP 3

Run

Add the plugin and run your tests as usual. A failure says what a person sees, and what the app left open.

// vitest.config.ts plugins: [channelstack()] $ npx vitest ✓ deploy.test.ts (1) 2.7s
