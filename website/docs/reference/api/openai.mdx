# OpenAI API

Every handle of the OpenAI fake: the `openai` fixture, the people and objects a test creates on it, and what they read and wait for. How to test a OpenAI app or agent, step by step, is in the [OpenAI guide](/docs/platforms/openai).

Each call is shown in every SDK's language, with its required options (the table under it lists them all). Arguments go first; options are TypeScript's trailing object, Python's keyword arguments and Rust's builder setters. The variable names are the ones the calls return elsewhere on these pages, so `user` is a `OpenAIUser` handle.

Besides the errors listed with each method, most methods can fail with [`action_requires`](/docs/reference/api/errors#action-requires), [`cross_workspace_credential`](/docs/reference/api/errors#cross-workspace-credential), [`fake_actor_in_live_world`](/docs/reference/api/errors#fake-actor-in-live-world), [`internal`](/docs/reference/api/errors#internal), [`invalid_argument`](/docs/reference/api/errors#invalid-argument), [`live_misconfigured`](/docs/reference/api/errors#live-misconfigured), [`live_not_allowlisted`](/docs/reference/api/errors#live-not-allowlisted), [`not_found`](/docs/reference/api/errors#not-found), [`session_not_found`](/docs/reference/api/errors#session-not-found), [`unauthorized`](/docs/reference/api/errors#unauthorized), [`unsupported_in_live`](/docs/reference/api/errors#unsupported-in-live): a bad request, a closed session, or live mode refusing or misconfigured.

### respond()

Script what the model answers: turns used in order, one per matching call, or a responder the test answers. Scripts are tried in the order they were added.

<CodeGroup>

```ts title="TypeScript"

```

```python title="Python"

```

```rust title="Rust"

```

</CodeGroup>

|---|---|---|---|
| `turns` | `OpenAITurnInput \| OpenAITurnInput[]` | no | positional |

| `timing` | `OpenAITiming` | no | option |
