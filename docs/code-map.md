# Code map

> The one place that says **where each piece of shared logic lives**. Before writing a function, look here. If what you need exists, use it. If it almost exists, extend it. Only create a new module when nothing here fits, and add it to this map in the same PR.
>
> Planned paths are marked *(planned)* until the phase that builds them. The phase review checks that this file matches the code.

## Rules

1. **One owner per concern.** Every row below has exactly one module. Two implementations of the same concern is a blocking review finding.
2. **Drivers don't share code with each other.** Shared behaviour moves into `server/src/core/`. A driver importing from another driver fails `pnpm check:deps`.
3. **Core never imports a driver.** Drivers register themselves with core.
4. **SDK runtimes mirror each other.** The TypeScript, Python and Rust runtimes have the same modules with the same names, so a fix in one is easy to find in the others.
5. **An SDK holds no server code, and the generator reads only the spec.** `pnpm check:deps` enforces both, along with rules 2 and 3 (`.dependency-cruiser.cjs`).

## SDK runtimes (`sdks/typescript/runtime/`, `sdks/python/channelstack/runtime/`, `sdks/rust/src/runtime/`)

The same modules with the same names in every language.

| Concern | Module | Notes |
|---|---|---|
| Transport | `transport` | Bearer token, retries while the server starts, error code → typed exception, a hook that sees every refusal with its request path (`onRefusal` / `on_refusal`, for a test integration), and reads whose refusals skip it (`unreportedRefusals` / `unreported_refusals`) |
| Launcher | `launcher` | `auto` / `attach` / `start`; finding the server binary and its per-platform package name |
| Client base | `client` | What generated handles share: `HandleContext`, the root client's `close`, the version check on connect. Rust's also has how arguments go on the wire (`IntoArg`, `enc`), the one request function (`send`), the builder every method returns (`Call`) and a handle by name (`Dyn`) |
| Credentials | `credentials` | A credential the test left out, from the environment: `CHANNELSTACK_SLACK_USER_{name}_TOKEN` with the person's name (`x-channelstack-credential` on the field) |
| Waiting and polling | `wait` | The one polling loop: cursor reads, timeouts, repeating a call a person would wait for (`retryWhile`), text matching for waits, a pattern as it goes on the wire (Python's and Rust's `pattern_on_wire`: a pattern's flags, inline ones like `(?i)` included, go in `flags`, as the server's patterns are JavaScript's), quiet checks (`untilQuiet`; `watching` makes it look for the whole window, and a timeout names what the agent left open). Every `waitFor…`, `latest…` and matcher uses it, and it holds the one settable default `timeout` and `quietFor` (`setWaitDefaults`, Python `set_wait_defaults`) that the Vitest plugin's and pytest's options set, so they reach every wait. Rust's `WaitState` is a handle's wait positions and its field handles' states, so `msg.thread()` is the same thread each time |
| Durations | `duration` | Parsing `"3s"`, `"750ms"` |
| Files | `files` | Reading fixture files and directories a test hands over (`readTree`, `readChanges`), and where relative paths start (`setFilesRoot`); a path that isn't there is an error, not no files. TypeScript and Python only: the Rust SDK sends what it is given ([#75](https://github.com/christian-bromann/channelstack/issues/75)) |

The TypeScript SDK's entry is `sdks/typescript/client.ts`, exported as the package root (`channelstack`) and as `channelstack/client`. With it go `sdks/typescript/types.ts`, the contract's type names the generated SDK has no type for (option bags, and the unions of handles, which `generated/channels.ts` holds), each read from the generated code; and `sdks/typescript/bin/channelstack.mjs` runs the platform's server binary. The Rust SDK is the `channelstack` crate (`sdks/rust`, in the repository's Cargo workspace, toolchain in `rust-toolchain.toml`); its errors are `runtime/error.rs` (a failed check is `Error::Expectation`), its matchers `src/expect/` (see Test integrations), and its launcher, like Python's, finds the binary at `CHANNELSTACK_SERVER_BIN` or `channelstack` on the `PATH`; neither bundles nor downloads one.
