Competitive analysis · v2 · 19 Nov 2026

Testing agents that live in Slack, GitHub and Linear

Who already solves end-to-end testing for channel agents, what is still open, and where channelstack fits. Built from eight research tracks:

  • about 40 tools and vendors
  • emulate's 70 issues and 349 PRs
  • a line-by-line split of the closed MDA local-stack PR stack (#1040–#1122)
  • the test suites of 10 agent frameworks
  • a sample of 28 agent apps, plus issue searches on about 25 more

Stars, downloads and counts were pulled on 2026-11-19. GitHub code-search totals are approximate. Numbers that come only from aggregators are marked "unverified". Companion notes: niche.md, framework-testing.md, app-developers.md, devx.md.

Bottom line

The real competitor is "build it yourself". Every serious team has built a harness for its own channels: OpenClaw (QA Lab, Crabline), Hermes (platform stand-ins), n8n (replay and contract tests), Open SWE (a fake Slack) and MDA itself (17.9k lines, closed). None of it is packaged for anyone else. The other 85% of agent apps mock the SDK or don't test, and they keep shipping the same bugs: duplicate replies on retry, replies outside the thread, a bot that responds to itself, streams finalized twice.

Don't rebuild the fakes; package the harness. Vercel Labs' emulate already has stateful Slack, GitHub and Linear APIs with signed events. What nobody ships is everything around them:

  • a standing local server at stable addresses
  • a browser client to chat with your bot
  • actors and assertions on what a person sees
  • delivery chaos (retries, redelivery, bad signatures)
  • a standard set of behaviour checks, wired into Vitest and pytest
  • the agent surfaces emulate rules out (Slack streams, agent sessions, Socket Mode), plus Notion, which emulate doesn't have

Position: channelstack is a local server, reachable through portless, built on emulate wherever emulate models state, and the shared version of what OpenClaw and Hermes each built for themselves.

What changed since v1

Four corrections

  • emulate is further along than the 0.12.3 version the stack pinned. v0.14.0 (2026-11-18) has:
    • signed Slack event_callback deliveries and block-actions, view-submission and event-retry simulators;
    • Linear Agent Sessions (#394);
    • GitHub App tokens and signed webhooks.
    Most of the closed stack's fake Linear (about 1.2k lines) would now be unnecessary.
  • Upstreaming is a bet, not a plan.
    • Of 143 outside PRs, 12 were merged (8%), and at least 11 more were reimplemented by the maintainer (#196 → #394).
    • 62 are still open, with a median age of 74 days.
    • The question "do you accept outside PRs?" (#399) has no reply, and there is no CONTRIBUTING file.
    • Built-in services can't be extended through defineEmulator.
    So channelstack has to serve the missing routes itself.
  • The HTTPS interception proxy is no longer the lead feature. Each SDK already has a base-URL option (Bolt slackApiUrl, slack_sdk base_url, Chat SDK apiUrl). With portless, one env var is enough. A transparent proxy stays as a fallback for code that can't change its base URL.
  • The conformance suite moves down. It makes the fakes trustworthy, but it doesn't attract users. OpenClaw already proves the approach: the same scenarios run nightly against real workspaces.

Landscape

Eight groups, two of them real competition

Main competitor · in-house

Harnesses teams build themselves

  • OpenClaw (~395k★): about 630 YAML scenarios over synthetic, Crabline and live transports, plus a mock-openai server and nightly live lanes with leased credentials.
  • Hermes: aiohttp stand-ins with Socket Mode and streams, and one _contract.py scenario suite with a driver per platform.
  • n8n: replays, plus Teams JWT forging.
  • Open SWE: a fake Slack in Playwright.
  • kodus: live tests across 5 git hosts.
  • MDA: 17.9k lines, closed.

All of them are expensive, and none can be reused by anyone else.

Foundation · OSS

vercel-labs/emulate

Apache-2.0, about 2k stars, 15+ services. Chris Tate wrote about half of all PRs, and outside PRs are merged 8% of the time. Its README rules out Slack streaming, Socket Mode and slash commands. Testing tools are stalled: record/replay (#62), MSW (#288) and snapshots (#60, #282). Chat SDK and centaur use it. Build on it, don't fight it.

Weekly npm: @emulators/core 299k, slack 43k, github 18k, linear 2.7k.

Commercial twins

Arga, Hue, Drizz, StateWeave

Funded and closed source. Arga raised a $10M seed (Aug 2026). LocalStack announced buying WonderTwin. They mostly test the agent's outbound tool calls through a base-URL or MCP swap, not channel ingress. Their fidelity claims have no published evidence.

Precedent · Microsoft

TestFlow and Agents Playground

TestAdapter/TestFlow (.send('hi').assertReply(...)) is the original "simulated user, assert on reply" API, but it runs in memory and skips the channel's wire format. Agents Playground is a local Teams client, manual only. Together they prove there's demand for a local client plus a test API.

Framework kits

Chat SDK, Bolt, Probot, Mastra, Flue, Pi

@chat-adapter/tests checks handler calls. Bolt has never shipped a test kit (bolt-python#380, open since 2021). Mastra and ElizaOS use mocks. Flue tested only inbound verification and has since removed it. Pi's Slack bot had no Slack tests. Pi's fauxProvider is the common way to fake the model.

Generic plumbing

Proxies and spec tools

Hoverfly, mitmproxy, MockServer, Prism, Microcks and Specmatic. None of them know Slack, GitHub or Linear semantics. Building blocks, not competitors.

Complement

Agent eval and simulation

LangWatch Scenario, LangSmith simulation, Braintrust and Promptfoo judge answer quality in-process. None goes through webhook ingress. channelstack tests behaviour in the channel, so they sit on top of it.

Different buyer

RL environment vendors

Deeptune, Halluminate, Plato and Collinear sell Slack and Jira clones to frontier labs for training. Low threat, and a possible source of scenarios.

White space

What is open, and how long it stays open

open

A packaged harness. OpenClaw and Hermes arrived at the same design on their own (fake provider servers, a scenario suite with a driver per platform, a wire-level fake model), but it stays inside their repos. Nobody offers it as a product.

open

A local chat loop for development. Today, testing a Slack bot means a dev workspace, installing the app, ngrok, and switching windows. The only local client that exists is for Teams (Agents Playground). A Slack-like browser client with an inspector and chaos buttons, at https://channelstack.localhost, is new.

open

Asserting on what a person sees, and delivery chaos. Matchers like toHaveRepliesFrom and toHaveStatus, plus retry, redelivery and forged signatures as test primitives. Only Hermes has them, internally. These catch the most common bugs across all the apps sampled.

open

Teams at the wire level. No fake exists anywhere. emulate's Microsoft service is OAuth only, and Microsoft's TestFlow skips the wire format. OpenClaw has a Teams fix blocked because it "needs tenant-backed delivery proof" (#199876). n8n forges Bot Framework JWTs by hand. It's a real gap, but channelstack is starting with Slack, GitHub, Linear and Notion.

open

Notion agents. emulate has no Notion service, and I found no Notion fake for comment mentions and integration webhooks. channelstack builds it as its own emulate service.

months

Slack agent surfaces (chat.startStream, agent sessions and Stop, Socket Mode). emulate's README rules them out today and only Hermes models them. Chat SDK users file streaming bugs (vercel/chat#1036). Vercel could close this when it needs to, so build it to be swappable.

open

A standard behaviour-check suite. Things like "replies once", "survives a 3-second retry", "ignores itself", "honours Stop", "refuses unauthorised clicks". Each one maps to a bug class found in real apps. Hermes's scenario names are nearly this list.

open

Linear agent tooling. Linear's own demo agents have no tests and say to try them in a real workspace.

Demand

The same bugs, everywhere

  • The population. There are about 5k–10k open-source agent apps in channels, and about 300–500 of them have 100+ stars, mostly active in 2026. Code-search hits: Telegram + LLM about 7.5k, Discord about 6.8k, Slack Bolt + LLM about 2.9k, Chat SDK adapters about 800, Teams about 620, Linear agentSession about 360.
  • How they test (sample of 28). 71% only mock the SDK, 14% have no channel tests, 11% use a fake server (Sentry's junior on msw, Paradigm's centaur on emulate), and 4% test live (OpenClaw).
  • The bugs that recur.
    • Duplicate replies: openclaw#1481, chatwoot#15450, mastra#18877, OpenHands#13358, eliza#37505.
    • Replies outside the thread: openclaw#1163, n8n#43054.
    • Bot reacting to itself: claude-code-action#794, kodus#1946, a pr-agent loop (#1528).
    • Missed triggers: OpenHands#12513, gemini-cli#172.
    • Stream finalized twice: openclaw#158103.
    • Check runs stuck or falsely green: claude-code-action#1679.
    All of these come from platform behaviour that mocks don't model.
  • Slack never shipped a test kit. bolt-python#380 has been open since 2021. node-slack-sdk#1031 was answered with "sign the requests yourself". About 120 GitHub repos are mock Slack servers.
  • Explicit requests are rare, but they exist. Dry-run mode (pr-agent#1237), "how to test this tool" (claude-code-action#503), tests for the Slack client (eliza#2403), and test webhooks that work while production fails (n8n#34204, dify#41752).
"given the lack of test kits, I have to understand how Slack signs" (node-slack-sdk #1031)

Not covered: Reddit (the archive API rate-limited every query). I found no discussion of emulate on HN or X.

Risks

What could sink it

  • OpenClaw packages Crabline and QA Lab. It has the reach (~395k★) to define the category. Mitigations: be framework-neutral, cover Linear and Notion, plug into every test framework, and approach them early as users rather than competitors.
  • Vercel builds the layer into emulate. ctate reimplements good outside ideas. Mitigations: depth on agent behaviour (streams, Stop, chaos, checks), Python and Go clients, and test-framework integrations, none of which an API-emulation project has much reason to pursue.
  • Building on emulate is fragile. Overlay routes such as streams have to write into emulate's state, and the API for that may change. Pin versions, keep the overlay small, and be ready to swap the store.
  • The UI could grow into product clones. Keep it functional: one neutral transcript view with working buttons, forms and raw JSON, and no attempt to copy each product's look.
  • Long-tail developers don't write e2e tests. The standard checks and the local chat UI have to deliver value before anyone writes a test.
  • Funded twin vendors move down to developers. The answer is open, self-hosted and CI-native. Keep the core open: LocalStack closing its community edition led to a fork with about 32k stars.
Recommendation

A first milestone that proves the gap

  1. The channelstack server: Slack at https://slack.localhost through portless, with one in-memory workspace. It stores state in emulate, and serves streams, agent sessions and Stop, Socket Mode, a delivery log and redelivery itself. GitHub, Linear and Notion (github., linear., notion.localhost) follow the same pattern.
  2. The browser UI at https://channelstack.localhost, plus the attach CLI (channelstack slack say --as ana …) and MCP: a channel view, the inspector, and chaos controls.
  3. The channelstack/vitest plugin and slackChecks(): fixtures in the test context, expect extended with channel matchers, and about 12 checks taken from the bug classes above. Models stay with each framework's own fakes.
  4. The proof: re-land MDA's channel tests on channelstack in about 5k lines instead of 13.8k, then show it to the teams behind junior, centaur and Open SWE, and to the OpenClaw and Hermes maintainers.
